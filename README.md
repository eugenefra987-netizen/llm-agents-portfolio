# LLM-агенты для реального бизнеса

**Евгений Бучацкий** · архитектор систем LLM-агентов

Проектирую системы ИИ-агентов, которые работают каждый день, а не только на демо.
Код рабочих систем закрыт — здесь устройство, решения и результаты.

**Моя роль:** постановка задачи и критериев качества, архитектура и рабочие процессы, организация разработки,
тестирование, аудит результатов и итерационное улучшение. Код по моим постановкам пишут AI-инструменты
(Claude Code, Codex); я отвечаю за то, что и зачем строится, и за проверку, что оно работает.

## Принципы
- **Модель предлагает — код проверяет — человек подтверждает.** У модели нет права самой записывать данные
  или совершать значимое действие: детерминированный контроллер проверяет результат и сохраняет,
  ключевые шаги (публикация, сделка) — за человеком.
- **Персональные данные не уходят за рубеж.** Российский контур обезличивает данные на входе; зарубежные
  модели работают только с обезличенными. Модель подключается через маршрутизатор — YandexGPT, GigaChat,
  DeepSeek, OpenAI, Claude — без правки кода.
- **Обучаемость, а не самообучение.** Поведение агента правят рекомендации владельца, а не переписывание кода.
- **Журнал всего.** Записи только добавляются; журналы решений и инцидентов — по каждому проекту.
- **Агенты печатаются из общего каркаса.** Охрана действий, сохранение через контроллер, память обратной связи,
  команды и связь с человеком — одинаковые у всех агентов; своё у каждого — только роль и проверки.
- **Внешние тексты — данные, а не инструкции** (защита от prompt injection). «Нет данных» ≠ «хорошо».

## Проекты

### 1. «Гид по миру» — система автоматизации турагента → [архитектура](SYSTEM.md)
Модульная система агентов: контент для турагента + подбор туров. 13 модулей, 6 уже работают,
контент-менеджер — в тестовой эксплуатации (первый агент, собранный на общем каркасе).
Каждый модуль автономен и с самого начала задуман частью целого — новые агенты подключаются без переделки системы.
У каждого агента своя память; задания между ними разносит рабочий стол по маршрутам, путь каждого задания записывается.

**Живой результат:** Telegram-канал [«Гид по Миру 🌍»](https://t.me/your_guide_to_the_world) — тексты пишет агент-автор.
- **Цикл автора:** утром сам запускается → читает отраслевые источники → сверяет с контент-планом → предлагает три темы
  (в том числе в Telegram) → по выбранной теме проводит отдельное исследование → пишет и проверяет факты.
  Статусы: **DRAFT** — готово к редактуре, **HOLD** — публиковать нельзя, пока не выяснены сомнения.
  Публикует человек.
- **Программный контроллер** — код, а не второй агент: ведёт стадии, выдаёт нужные инструкции к каждой,
  сохраняет черновики и ревизии, держит очередь и журнал. Модель решает творческие задачи; записывать сама не может.
- **Память обратной связи.** Владелец объясняет замечание обычными словами → модель предлагает рекомендацию
  (правило, когда подходит и когда нет, пример «было → стало», метки) → владелец утверждает командой →
  контроллер сам копирует слова владельца из переписки как первоисточник. Сейчас 62 рекомендации; к каждому этапу
  приходят подходящие по жанру. Модель ведёт журнал: какую рекомендацию применила и как.
- **Эффект** (наблюдение владельца, не A/B-тест): в начале тексты требовали 7–10 редакций, до 13;
  в недавней серии около 16 публикаций понадобились всего 3 точечные правки. 100+ публикаций в канале.
- **Кейс «Саккара» (29.10.2026): агент не опубликовал выдумку отраслевого СМИ.** Утром он взял из ленты новость:
  «в Саккаре впервые открыли для туристов гробницы лекарей, билет с 1 ноября — 600 и 400 фунтов» — и предложил темой.
  Перед текстом проверил египетские источники, подтверждения не нашёл, пост писать не стал и сам отметил, что тему
  надо было проверить до предложения. Причём сначала, прочитав лишь два источника, честно написал «подтверждения не нашёл»,
  а не «новость ложная»: по его правилам такой вывод требует пяти прочитанных источников. После расширенной проверки
  (исходная статья и ещё 8 источников, 4 из них египетские) вывод: статья склеила две реальные новости — находку гробницы
  чиновника, которую для туристов не открывают, и осмотр гробниц, которые пока только документируют, — а «открытие»
  и цены не подтверждаются ни одним источником.
- Связь с агентом — и из Telegram: сообщение (в том числе голосовое) продолжает его рабочую сессию.

**Визуальные продюсеры** — четыре работающих интерактивных прототипа (три — визуальные истории к постам, один — офферы).
По тексту поста они определяют жанр и главную мысль, придумывают визуальную концепцию и делают серию изображений
с разной композицией, палитрой и типографикой. Результаты — в том же канале. Передача текста к ним пока ручная;
серверная интеграция в общий конвейер — следующий этап.

**Контент-менеджер (тест с 31.10.2026).** Собран на общем каркасе: утренняя сводка, контент-план, слежение за событиями,
новостями и конкурентами. В первый же день предложил тему по календарю событий (День мёртвых в Мехико, даты проверены
по официальному сайту), которую пропустил автор. Отсюда следующий шаг: календари сезонности и событий подаёт модели
сама система — сигналами в каждом задании, а контроллер проверяет, что ни один сигнал не пропущен.
### 2. Аналитик отелей: «тот ли это отель» → [как устроено](HOTELS.md)
Знать про отель то, что знает опытный турагент, прочитавший все отзывы, — и не перепутать его с однофамильцем.
*Работающий прототип на этапе валидации.*
- **Паспорт отеля** собирается из данных туроператора: названия (и бывшие), курорт, звёзды, точка на карте, адрес, телефон.
- **Карточка идентификации:** каждая страница с отзывами (десяток площадок) сверяется с паспортом по сильным
  и слабым признакам. Уверенно тот самый — отзывы засчитываются; чужой — отброшен; **сомнение — отзывы не засчитываются,
  случай уходит на проверку модели**, которая открывает страницы и выносит вердикт.
- **Рейтинг считает формула, не модель:** модель только размечает проверенные отзывы (пункт, плюс/минус, тяжесть 1–4, цитата).
- **Аудит:** агент-аналитик дважды в день ищет повторяющиеся ошибки сборщика; второй агент делает выборочные проверки
  (чужих среди засчитанных — 0 из 118 и 3 из 127; все три — соседние отели той же сети, причина закрыта). Каждое новое правило сверки сначала прогоняется
  на всех прошлых вердиктах аналитика.

630+ отелей в базе, в очереди ~1300 (Турция, Египет, ОАЭ, Таиланд, Вьетнам, Мальдивы, Греция).

### 3. Исследовательский торговый агент (Мосбиржа) → [результаты](livermore.md)
Авторская торговая система переведена в строгие правила и проверена на 7 годах истории.
Решения о сделках принимает код, ИИ — аналитик. Лучший портфель: 100 000 ₽ → 343 000 ₽ за 2019–2026
при худшей просадке −17% (индекс за тот же срок — 89 000 ₽). Исследование, реальной торговли нет.
