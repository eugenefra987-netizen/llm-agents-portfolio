# «Гид по миру» — система автоматизации турагента


Одна система, которая одновременно решает две задачи: **создаёт контент** для турагента и **подбирает туры**.
Задачи связаны: подборы и база отелей — сырьё для контента, контент приводит клиентов на подбор.

## Принцип: модули, а не монолит
Каждый агент — самостоятельный модуль: работает автономно, у него своя роль, свои входы и выходы, свой журнал.
Модули с самого начала проектируются как части одной системы, поэтому новый агент подключается
без переделки остальных. Масштабирование закладывается при проектировании, а не «потом перепишем».

## Каркас агента: агенты «печатаются», а не пишутся с нуля
Связка «модель + контроллер» сначала была отлажена на агенте-авторе, затем вынесена в общий каркас:
- **охрана действий** — модель может только читать разрешённое и искать в интернете; записать что-либо она может
  лишь через контроллер и только по команде человека;
- **хранилище «только добавление»** — новая версия ложится новой строкой, история не переписывается;
- **память обратной связи** — рекомендации владельца с условиями применения; первоисточник каждой — его слова дословно,
  их контроллер копирует из журнала сессии сам;
- **команды, записка при открытии сессии, связь через Telegram**.

Своё у каждого агента — только профиль: роль, инструкции, виды данных и их проверки. Первый агент на каркасе —
контент-менеджер (31.10.2026).

## Данные: у каждых данных один хозяин
Агенты не пишут в базы друг друга. Каждый ведёт свои данные; другим достаются копии только для чтения,
которые обновляются сами. Поэтому любой модуль можно вынуть и использовать отдельно — например, автора как
самостоятельный продукт.

## Конвейер контента: задание с единым ID
Единица работы — **задание** с уникальным ID и площадкой публикации. Задание идёт по цепочке,
каждый агент дополняет его своей частью:

1. **Контент-менеджер** собирает утреннюю сводку, ведёт контент-план (3 месяца — направления, месяц и неделя —
   подробно, по дням публикации) и расписание, выдаёт задание.
2. **Автор** пишет текст. Если нужны отели — данные даёт **аналитик отелей**.
3. **Визуал-продюсер** придумывает визуальную историю и делает изображения (фактура мест — от **Атласа**);
   **видео-продюсер** — видео и рилсы по заказу контент-менеджера.
4. **Публикатор** выкладывает в назначенное время на нужную площадку.

Задания разносит **рабочий стол** — часть контент-менеджера (главного редактора). Маршрут выбирает контент-менеджер,
исполняет его код стола: передать, дождаться, записать путь, поставить в очередь публикатору. Так передача заданий
работает как часы, даже когда сессии с моделью нет. Заказ офферов (подборок туров) — тоже задание на столе
с пометкой «кто заказал и для чего».

**Около пяти площадок публикации; для каждой контент уникален** — один и тот же пост не дублируется по соцсетям.

**Профиль турагента** — единая точка правды о позиционировании и образе турагента. Ведёт **маркетолог**;
читают контент-менеджер и автор (например, контент-менеджер предлагает публикации, усиливающие авторитет турагента).

## Человек в системе: единый интерфейс
Общая панель управления, через которую видны все агенты: мониторинг, общение с каждым, обратная связь,
пожелания и согласования. Каждый агент связан с человеком отдельно.
Ключевые точки согласования — текст автора, визуал; сейчас текст автора сохраняется только командой человека
(владелец перечитывает каждый текст).

## Два контура: российский и внешний
| Контур | Где работает | Что делает |
|---|---|---|
| **Внутренний (российский)** | российский сервер, российская языковая модель | принимает обращения клиентов (голосовая анкета, сайт), транскрибирует, **обезличивает**, хранит персональные данные; ассистент турагента |
| **Внешний** | зарубежные модели (Claude, OpenAI и др.) | творческая и аналитическая работа: тексты, визуал, подбор туров, база отелей — только на обезличенных данных |

Персональные данные клиентов не покидают российский контур (152-ФЗ «О персональных данных»).

| **Сборщик отелей** (программа) | собирает карточки, паспорта, отзывы | очередь отелей | карточки | **работает** |
| **Аналитик отелей** | следит за сборщиком, ошибки → инженеру; собственный рейтинг | карточки, отзывы | рейтинг, отчёт об ошибках | **работает**: 630+ отелей, очередь ~1300 |

| **Ассистент турагента** (рос. контур) | приём и обезличивание анкет; оперативная информация, помощь в подборе, предупреждения | голосовая анкета, сайт | обезличенный запрос, подсказки | в планах |
| **Инженер** (агент-разработчик) | читает журналы агентов, исправляет, предлагает правки | журналы, отчёты | исправления | **работает** |
| **Сайт** | приём заказов, витрина | заявки клиентов | заказ ассистенту | в планах |

## Общее для всех модулей
- **Модель предлагает — код проверяет — человек подтверждает** значимые шаги.
- **Обучаемость, а не самообучение:** поведение агента меняют рекомендации владельца, а не правка кода.
- **Журналы** у каждого агента; инженер читает их и предлагает исправления.
- **Маршрутизатор моделей:** любой модуль можно перевести на другую модель (YandexGPT, GigaChat, DeepSeek,
  OpenAI, Claude) без правки кода.

## Доказательства, что это работает
- Автор: с 25.10.2026 ежедневно запускается сам утром (новости → темы → тексты); 100+ публикаций в канале,
  ревизии принимаются почти без правок.
- Автор остановил ошибочную отраслевую новость: перед текстом проверил источники и выяснил, что новость неверна.
- Контент-менеджер в первый день теста предложил тему по календарю событий, которую пропустил автор, —
  и показал, что календари нужно подавать модели системно, сигналами в каждом задании.
- Аналитик отелей: 630+ отелей; каждая страница сверяется с паспортом отеля; правила сверки уточняются по разборам
  аналитика и проверяются на всех его прошлых вердиктах перед включением.
